# Workspace decisions

- **Keep the existing platform.** FastAPI, plain browser JavaScript and SQLite remain the application. Render retains its native Git deployment, single Uvicorn worker and persistent disk. No new launchers, service wrappers, paid sources or authentication flows.
- **Editor values and revisions are one snapshot.** A refresh may replace a clean editor and its revision together. Pending edits retain the base they were written against; server changes require visible resolution. The server's optimistic `409` check remains mandatory.
- **Independent browser recovery.** Immutable localStorage records are scoped to one editor, job and version. Write and verify the replacement before removing that editor's prior record. Acknowledgements affect only their editor's saved version; other records are visible for recovery. Legacy maps remain intact after verified conversion. Recovery does not submit another tab's text automatically.
- **Retain import resolutions.** SQLite schema v2 adds resolution JSON to the existing import-conflict table. History and exports include original versions and resolution date/snapshot. Older resolved records whose historical snapshot was never stored explicitly report that limitation.
- **Field evidence dates are independent.** Preserve omitted source fields and explicit requirements in SQLite, with references to retained payloads and original dates. Listing success, attempt, historical import date, description and requirement provenance have different meanings. Recently verified uses only actual successful checks.
- **Documented fit is evidence, not probability.** Version v2 keeps 20 family, 50 responsibility and 30 mandatory-requirement points. Independent clauses retain their original quotation and mapped CV evidence. Partial support is explicit. Topic mentions do not establish specialist actions or tools. Unknown source data, absent candidate evidence and documented incompatibility stay distinct. Caps and withheld scores remain; no score distribution target is used.
- **Preparation uses relevant evidence pairs.** Generated suggestions use supported listing clauses and their CV references; unresolved requirements are a separate checklist. Existing drafts are authoritative and never regenerated on refresh. No invented contact details, availability, qualifications or achievements.
- **One presentation and filter policy.** Search, details, audit and export derive from the same current presentation. Employment types are canonical memberships; mixed listings appear in both relevant views, missing types are explicit, and old query spellings remain compatible. CSV/XLSX cells retain formula-injection protection.
- **Phone priority follows the task.** Compact discovery rows, source collection health, source choice and record search come first. Larger source-flow and coverage sections are disclosures on phones. Details retain the desktop pane/mobile full-screen behavior; keyboard, focus, reduced motion and touch targets remain native and visible.
- **Rollout protects production.** Production was captured using the authenticated SQLite backup endpoint. Migration and restoration are rehearsed on isolated copies with row counts, original-field comparisons and payload digests. All application mutation tests use isolated storage. External collector outages are reported separately from application verification.
