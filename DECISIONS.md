## Editor state and ownership

Each editor/job owns base/revision, pending, inFlight, recovery key and feedback. Shared list data cannot redefine dirty editor values. “Saved” requires validated acknowledgement, not merely HTTP 200.

| State/event | Transition and ownership |
| --- | --- |
| Clean + refresh | Replace displayed values/base/revision together. Existing drafts remain authoritative. |
| Input or explicit action | Merge pending; persist recovery immediately before debounce/request. Dirty → saving after 300ms, or immediately for explicit action. First note creates Saved. |
| Saving + new keystrokes | Submitted patch belongs to inFlight; newer changes remain pending. Recovery merges inFlight then pending, preserving newer values. |
| Valid acknowledgement | Require matching job, increasing integer revision, valid fields and acknowledged values. Advance base, clear acknowledged inFlight only, preserve newer pending/other editors. Submit remaining patch against correct new base. Never regress a newer observed server revision. |
| Invalid acknowledgement/network/timeout/401 | Return inFlight to pending with original base, show failure/Retry. Explain sign-in failure; no promise of full offline search. |
| Dirty refresh/409 | Keep local text/base; expose current server/local comparison and stop auto-retry. “Save my edits over this version” explicitly rebases; “Keep server version” clears this editor's patch. |
| Recovery available | Show competing versions/base/date/full text. Loading enters comparison, never automatic submission. Discard only selected record; failed removal remains visible. |
| Browser storage failed | Keep in page memory; say edits are only on this page. Offer download/manual copy and warn before leaving unpersisted work. Server acknowledgement can still finish saving. |

Stage corrections retain history. Import history retains original notes/stage, resolution/date. A historical snapshot never captured cannot be reconstructed or implied by current data.
