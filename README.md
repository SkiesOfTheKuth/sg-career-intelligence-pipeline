# SG Career Intelligence

Private Singapore job discovery and application tracking for Dechsurang. FastAPI serves a plain HTML/CSS/JavaScript workspace; SQLite is the authoritative store.

## Run

Install `requirements.txt`, set `AUTH_USERNAME`, `AUTH_PASSWORD`, and optionally `DATABASE_PATH`, then run `uvicorn app:app --host 127.0.0.1 --port 8000 --workers 1`. Existing login defaults are preserved for compatibility. The local database defaults to `data/career.sqlite3`.

First startup imports every ID in `processed_master_jobs.json`, repairing facts against retained source URLs and identifiers in `mcf_jobs_raw.json`, `apify_jobs_raw.json`, and `cultjobs_raw.json`. Source text remains complete where retained; partial search snippets and unmatched excerpts are identified. The legacy input remains an archival migration source, not presentation data. Subsequent startups use SQLite without overwriting collected updates.

## Data and recovery

Applications use revision-checked writes. `409` responses include the current server copy; browser edits remain in local recovery until acknowledgement. Every editor binds its displayed values to a base snapshot and revision. Clean refreshes update both together; dirty refreshes expose conflicts. Save acknowledgements are validated before recovery is removed; corrupt records are isolated and storage failures expose downloadable unsaved work without claiming persistence. Immutable recovery records belong to one editor/job/version, so a successful save cannot delete another tab’s edits. Legacy recovery maps remain after verified conversion, and competing versions are available for explicit review. A first note creates a Saved application and immediately exposes its history. Acknowledgements refresh open history without replacing active inputs; completed import reviews show saved feedback. If another editor already resolved the same import, explicit conflict rebase preserves selected text and drops only the consumed resolution command, retaining the first historical resolution. Closed applications preserve notes, outcome, job snapshot, drafts, and stage history. Existing `sg_career_shortlist_v2` browser data imports automatically using content-hash receipts; differing notes/stages are preserved for review. Authenticated `GET /api/applications/{job_id}/history?offset=0&limit=25` includes original imported notes/stage, resolution and date, including resolved versions; application exports include the complete retained history.

SQLite uses WAL, FULL synchronous writes, and explicit write transactions. A consistent backup and a full restore rehearsal run on initial migration, after each 12-hour refresh, on graceful shutdown, and through authenticated `GET /api/backup`. Three recent snapshots are retained under `/var/data/backups`; the disk itself also has Render's daily snapshots. SQLite backups are the database recovery source. `Store.restore_backup(source, new_destination)` refuses to overwrite an existing database, restores via SQLite's backup API, and compares row counts and content digests of every table. To restore a service, place the verified restored database on its persistent disk, set Render's native `DATABASE_PATH` to that new path, and redeploy.

The refresh schedule is stored in SQLite and owned by the FastAPI lifespan. Overdue work resumes after restart. MyCareersFuture retains its free 12-hour refresh. The separately authorized seven-day campaign runs through the same FastAPI lifespan and SQLite store and retains its original **30 October 2026, 21:37:21 SGT** deadline; see [CAMPAIGN.md](CAMPAIGN.md) for caps, source-specific validation and collection bounds. The 24 October correction removes local robots/DNS/redirect and remote-isolation admission gates; the official crawler's optional robots setting is false. Actual provider failures remain recorded outcomes. Existing evidence remains labelled for recheck. A limited search result cannot establish closure of an absent listing. Failed checks preserve prior facts and successful verification times, and record source errors. Partial responses retain omitted descriptions and explicit requirements with their original field provenance. Successful listing checks do not refresh the dates of retained content. Schema v2 applies an additive transaction and idempotent source-field backfill from retained evidence; original payloads remain unchanged. Paid collection is admitted only by the persisted campaign policy; an unprepared or paused campaign launches nothing.

## Sources audit

The authenticated `/sources` page maps sources → retained evidence and assessment → discovery and applications. Counts come from SQLite, not raw import file sizes. Select a source to inspect collection method, scope, dates and failures. Coverage shows exact counts for retained descriptions, requirements, salary and successful checks within 24 hours. Search, filter and paginate records; open an inspector for cleaned fields, original URLs, collector query context, the score breakdown and paginated retained payload versions. Historical collector records can contain inserted defaults; the inspector explicitly distinguishes them from employer facts. Payloads render as text and credential-like keys are redacted.

Campaign counts separate production imports from isolated validation. Source outcomes, next runs, charges, reservations and the stop time remain inspectable. The paginated discovery-lead list filters by source and production/validation scope; its inspector exposes retained returned evidence and parent context without promoting incomplete pages or snippets into Find roles. Collection dates and employer posting dates are distinct. Supplemental source validation uses the existing pilot allowance without changing an active production campaign's mode.

`GET /api/audit/sources`, `GET /api/audit/records` and `GET /api/audit/records/{job_id}` require the existing login. The last 100 collection runs expose per-query success/error evidence. Manual checks use the same `POST /api/sync` path as automatic work: four MyCareersFuture searches (Thai, Marketing Executive, Social Media Executive, Public Relations), up to ten results per search. This is not continuous monitoring or a recheck of all stored vacancies. An in-flight task survives request cancellation; graceful shutdown waits for it, and an interrupted-run marker triggers a retry after a hard restart.

## Assessment and exports

Assessments are reading aids grounded in the verified résumé. Relevant requires supported family alignment and mandatory requirements. Unknown requirements and incomplete source text remain Check requirements; unsupported mandatory language and specialist accounting requirements prevent top recommendations. Company geography and search queries cannot imply Thai requirements. Historical fixed check dates are identified as source-record dates, not new verification.

The `documented-fit-v2` score in `fit_score.py` uses a visible policy: role family 20 points, distinct documented responsibility overlap 50, explicitly supported mandatory requirements 30. Independent action-and-scope clauses are assessed separately; compound statements expose partial support, preserve the full quotation, and award no credit for unsupported clauses. Required experience remains mandatory when only its industry is preferred; equivalent requirement headings stop duty parsing. Each documented domain counts once even when duties combine previously credited domains. Every supported duty/requirement quotes the listing and cites CV evidence. Repeated supported task groups count once. Topic words alone do not establish specialist design, animation, video, tool or finance skills. Degree alternatives and Unicode bullets are normalized for comparison; company/recruiter boilerplate is excluded. Unknowns earn no points, which means unproven rather than incapable. Missing required language/qualification/experience or seniority evidence caps the total at 39; unresolved/missing mandatory requirements, unclear duty sections or an adjacent family cap it at 59. Incomplete descriptions or no identifiable duties withhold the score. Preferred qualifications are listed without adding points. Pay, prestige, geography and freshness never increase fit. Scores are provisional where evidence is unresolved, are not empirically calibrated hiring probabilities, and can miss nuances in unusual source wording. The breakdown exposes that uncertainty for review. Recommendation order uses fit groups then documented score; all APIs and exports derive the same current version at read time without modifying retained source payloads.

FastAPI lifespan prepares bounded in-memory assessment caches before readiness. This keeps the first user's search from paying the full initial assessment cost. Cache keys include the source text and requirements; changed source evidence is assessed again automatically.

Salary thresholds use advertised SGD minimums. Annual pay including `/yr` is normalized to monthly equivalents. Daily/hourly rates remain in their original units; unverified currencies and units cannot satisfy a monthly SGD filter. No minimum salary is assumed.

Search and export use one server filter function. Employment types are distinct memberships, including mixed freelance/employment listings; older combined filter values still work. Recently verified sorts by actual last successful check, with unverified records last. Application export supports selected IDs and stage, and includes notes, next action, follow-up date, original link, drafts, outcome, and history. All CSV and Excel exports protect against formula injection. Application exports include the saved job snapshot. XLSX values above the native cell limit retain their full text in labelled, ordered continuation parts on a separate worksheet, while the main sheet keeps one record per application. Text containing characters that XML cannot represent is retained there as a labelled JSON string; rejoin its ordered parts, remove only labelled formula prefixes, then decode JSON to recover the exact original. The workbook includes these reconstruction instructions. CSV and stored text remain unchanged. `generate_workbook.py` creates offline exports through the same presentation/export code.
